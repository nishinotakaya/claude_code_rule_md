# デュアル AI 意思決定（Claude Code + Codex CLI）

重要な方針決定・設計判断では、以下のプロセスを標準とする。

```
Claude Code（主導）        Codex CLI（セカンドオピニオン）
    │                              │
    ├─ 1. 方針・設計を立案          │
    ├─ 2. Codex に意見を求める ────→ 3. 方針を評価・代替案を提示
    ├─ 4. 意見を統合し最終決定 ←────┘
    └─ 5. 確定した方針で実行
```

## 手順

1. **Claude Code が方針を立案**: 要件分析、設計案、実装方針を策定する
2. **Codex CLI に依頼**: Bash で呼び出す

   ```bash
   # --skip-git-repo-check --sandbox read-only を必ず付ける
   # （--full-auto は非推奨警告が出て、信頼ディレクトリ外では失敗する）
   # 標準入力は < /dev/null で閉じる（閉じないと入力待ちで止まる）
   cd <リポジトリルート> && \
   codex exec --skip-git-repo-check --sandbox read-only "
   以下の方針についてセカンドオピニオンをください。
   問題点・リスク・代替案があれば指摘してください。

   ## コンテキスト
   <背景・要件の要約>

   ## 提案方針
   <Claude Code が立案した方針>

   ## 確認したい観点
   - この方針のリスクや盲点はあるか
   - より良い代替アプローチはあるか
   - 見落としている依存関係や影響範囲はないか
   " < /dev/null
   ```

3. **Codex が評価を返す**: 賛同・懸念・代替案
4. **Claude Code が最終決定**:
   - 賛同 → そのまま実行
   - 有益な指摘 → 方針を修正して実行
   - 意見が分かれた → 両論併記して理由を明記し、社長（ユーザー）に判断を仰ぐ

## 適用範囲

| シーン | 必須 / 推奨 |
|---|---|
| 設計・アーキテクチャ判断 | 必須 |
| 複数の実装アプローチがある場合 | 必須 |
| リスクのある変更（DB 変更、API 契約の変更、テナント境界に触れる変更） | 必須 |
| 単純な修正・明らかな実装 | 推奨（スキップ可） |
| バグ修正で原因が明確な場合 | スキップ可 |

## 原則

- **Claude Code が最終意思決定者**。Codex は助言者
- Codex の意見を鵜呑みにしない。根拠を評価し、妥当なものだけ採用する
- 採用 / 不採用の理由を `tasks/todo.md` に記録する
- レビュー文章の添削に使うときは、事実（ファイルパス・行番号・コード）を Codex が変えていないか必ず再確認する
