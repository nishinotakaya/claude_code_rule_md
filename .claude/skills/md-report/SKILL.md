# md レポート標準手順

「md に起こして」の一言で、毎回同じ品質・同じ場所にドキュメントが出るようにする。

## 出力先

- プロジェクト作業の記録 → そのリポジトリの `docs/` 配下（無ければ作成）。`docs/` はコミット対象外
- レビュー結果 → `docs/reviews/PR<番号>-レビュー結果.md`
- テスト証跡 → `docs/test_evidence/<機能名>/`
- e-learning の上流文書・進捗 → `tech-put-app/docs/e-learning/`
- ファイル名: `YYYY-MM-DD_<内容が分かる日本語>.md`

## 見出し構成テンプレ

```markdown
# <タイトル>（YYYY-MM-DD）

## 結論サマリ
3 行以内。読者がここだけ読めば足りるように。

## 目的 / 背景
なぜこの調査・作業をしたか。

## 詳細
やったこと・分かったことを時系列でなく論点別に。

## 根拠・エビデンス
- 実行コマンドと結果の要約（生ログ全文は貼らない。長い場合は保存先パスを参照）
- スクリーンショットはファイルパス参照
- コード根拠は `ファイルパス:行番号` 形式

## 未解決事項 / 次のアクション
残っていること。無ければ「なし」と明記。
```

## ルール

- 生ログ・巨大な JSON をそのまま貼らない。要約 + 保存先パス
- 認証情報・パスワード・トークンは絶対に書かない（seed のテストアカウントも本番では無効なことを書く）
- 既存の同テーマ md があれば新規作成せず追記・更新する（世代違いファイルを増やさない）
- 書き終えたら保存先パスを 1 行で報告する
