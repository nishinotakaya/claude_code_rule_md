# LLM が書いたコード専用のレビュー観点

> このプロジェクトではレビュー対象の大半が AI 生成コード。LLM は人間と違う壊し方をするので、観点を分けて持つ。

## 1. 未完了リファクタ（LLM 最大の失敗モード）★最優先

LLM はシンボルを rename / 削除したとき、自分が開いたファイルだけを直して他を放置する。

1. 差分で rename / 削除されたシンボルを列挙する
2. 旧名でリポジトリ全体を grep する
   ```bash
   grep -rn "旧シンボル名" --include="*.rb" --include="*.ts" --include="*.tsx" --include="*.erb" .
   ```
3. 差分に含まれていないファイルにヒットしたら未完了リファクタ

機構（early-return ガード / 権限チェック / 重複排除）を消したときも同じ。他ファイルの等価ロジックを grep し、「3 箇所あったうち 1 箇所を消し、残り 2 箇所は意図的に残した」と件数で言えるか。

フロントとバックエンドの両方に跨る契約（API のキー名・ステータス）を変えたなら、相手側リポジトリも grep する。

## 2. テストを緑にするための改ざん

| 症状 | 具体例 | なぜ危険か |
|---|---|---|
| アサーションの弱体化 | `expect(x).to eq(42)` → `expect(x).not_to be_nil` | 何も検証していないテストが緑になる |
| 緩い matcher への置換 | `eq` → `include` / `be_truthy` | 同上 |
| 期待値を実装に合わせた | 期待値を新挙動に書き換えたのに正当化がない | 仕様変更とバグを区別できない |
| skip / pending の追加 | `xit` / `skip` / `pending` が差分に入っている | 落ちるテストを消して緑にした |
| 対象を呼ばないテスト | 対象関数を 1 度も呼んでいない | 無効票 |

検査: テストファイルの diff で `-` 行（削除された行）を必ず読む。強いアサーションが消えていないか。

## 3. mock の対象誤り

定義元ではなく、テスト対象が呼ぶ経路を mock する。`allow(SomeModule).to receive` の対象が実際に呼ばれる経路と一致しているか。mock が効かず実 HTTP / DB が走ってもテストが緑になる「誤った green」に注意。

## 4. 早期 return によるサイレントスキップ

差分内の新規 early-return すべてについて、スキップされるケースが本当に no-op か検証する。ログも出さずに黙って抜けていないか。呼び出し側は「処理された」と思っていないか。

## 5. ハルシネーション / シグネチャ変更された API 呼び出し

- 引数の個数・順序・存在しないキーワード引数
- 存在しないメソッド / gem / npm パッケージ（推薦パッケージの数 % は実在しない）
- 検査: 新規に追加された import / require / gem を 1 つずつ実在確認する

## 6. コンテキスト由来の一貫性崩れ

- 同じ概念に 2 つの名前（`user_id` と `userId` が差分内で混在）
- 既存ヘルパーがあるのに同じことを新規実装（`src/lib/` `app/controllers/concerns/` を grep）
- エラーハンドリングの方式が周辺と違う（既存は `render_not_found` なのに `raise`）

## 7. 過剰防御（AI レビューを全採用した痕跡）

| 症状 | 見分け方 |
|---|---|
| 過剰防御 | 呼び出し側が型で保証しているのに関数内で再チェック |
| YAGNI 違反 | 起こり得ないケースのハンドリング・使われない拡張ポイント |
| 一貫性崩壊 | この関数だけ異常に防御的 |

判断: 「この入力が実際に来る経路はあるか」を呼び出し側から辿る。無ければ削除を提案する。

## 8. AI が 1 件も指摘しなかった変更は逆に警戒する

AI レビュアーが見逃すのは「仕様を知らないと判定不能」なもの（空配列時にスキップするのが仕様、429 だけリトライが仕様、ページネーションの 1 件ずれ）。PR ごとに「仕様上の不変条件を 3 行」書き、それへの適合だけは人間が必ず見る。

## 9. チェックリスト

- [ ] rename / 削除したシンボルを旧名で全体 grep した。差分外にヒットがない
- [ ] 機構を消した箇所について、他ファイルの等価ロジックを grep した
- [ ] テストの diff の `-` 行を読んだ。強いアサーションが消えていない
- [ ] skip / pending / xit が差分に入っていない
- [ ] mock の対象が実際に呼ばれる経路になっている
- [ ] 新規 early-return のスキップケースが本当に no-op
- [ ] 新規 import / gem / パッケージが実在する
- [ ] 既存ヘルパーの再実装になっていない
- [ ] 過剰防御になっていない（その入力が来る経路が実在する）
