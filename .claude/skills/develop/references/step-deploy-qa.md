# STEP 8〜10: マージ・デプロイ・QA

## STEP 8. マージ（CTO）

1. worktree ブランチを push し、PR を作る（`.github/pull_request_template.md` を埋める）
2. フロントとバックエンドの両方を変える機能は **バックエンド PR → フロント PR の順**
3. レビュー承認後、ベースブランチへ `--no-ff` でマージする。マージ後の作業ブランチは削除する
4. 直接 push・force push はしない（`.claude/rules/git/`）

## STEP 9. デプロイ準備・デプロイ

- 環境変数の追加があれば `.env.example` に変数名だけ足し、デプロイ先にも設定したことを確認する
- `gitleaks git --staged --no-banner --redact --exit-code 1` が 0 件（値は出力しない）
- マイグレーションは `db:migrate` → `db:rollback` → `db:migrate` で戻せることをローカルで確認してから
- デプロイの実手順は各リポジトリの README / `.claude/rules/project/` に従う（バックエンドは `heroku.yml` がある）
- デプロイ後: ビルドログにエラーが無いこと、ヘルスチェック（トップ画面・ログイン API）が応答すること。失敗したらロールバックして報告する
- **本番データを書き換える検証（同期・取込・リセット）は実行前に一言断る**

## STEP 10. QA・エビデンス（qa）

```
デプロイ後の動作確認を実施してください。

## 対象
- 環境: <ローカル / ステージング / 本番> <URL>
- 変更内容の要約: <...>
- 受け入れ基準: <STEP 1 のもの>

## 手順
1. /auto-test の手順で Playwright を回す（PC 1440×900 とスマホ 375 幅）
2. 受け入れ基準を 1 項目ずつ操作し OK / NG / 未確認 を分ける
3. 証跡を docs/test_evidence/<機能名>/ に保存する（png・results.json・TEST_REPORT.md）

## 出力
- 項目ごとの結果、証跡の保存先、NG の原因と再現手順
- 「確認できなかったもの」は正直に「未確認」と書く
```

QA が NG を返したら、自動で直さず、まず社長に状況を報告してから修正に入る。

## 完了報告（CTO → 社長）

- 変更内容の要約
- QA 結果（件数・NG の有無）
- PR の URL、確認用 URL
- 残っていること（未確認・次フェーズ送り）
