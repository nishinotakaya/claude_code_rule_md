# AI ミス再発防止

毎セッション、作業着手前に読む。とくに次の場面では強制参照:
- 破壊的操作（DB / git / ファイル削除）
- デプロイ・本番データに触れる検証
- 「怒りサイン」検知時（`.claude/rules/core/mindset.md` の表）

プロジェクト固有の教訓は `tasks/lessons.md` に積む。ここは **型** だけ。

## 過去の事故の型

### 1. 本番 DB のリセットでデータ消失
- 何: 権限エラーの修正で DB アドオンを作り直し、ユーザー・受講データが全消失
- 教訓: 破壊的操作（DB / `git reset --hard` / `rm -rf`）は影響範囲を文章化 → 承認 → 実行。非破壊的解決を先に探す。`.claude/hooks/guard-bash.sh` がブロックしたら回避しない

### 2. 「フロントから操作してください」と返した
- 何: 自分でできる調査・実行をユーザーに丸投げ
- 教訓: ローカル完結（DB 読み / grep / 再起動 / テスト）は即自分で実行。例外は認証情報入力・ブラウザのログイン・物理デバイスだけ

### 3. アプリ・環境の取り違え
- 何: 別アプリを本番扱いして環境変数を投入した
- 教訓: 本番 URL は設定ファイルから逆引きする。ドキュメントのアプリ名・ポートは古い前提で疑い、`docker-compose.yml` / `heroku.yml` / `vercel.json` の現物で裏取りする（テックプットの `CLAUDE.md` に書かれたポート 3001 と `docker-compose.yml` の 3013 が食い違っていた実例）

### 4. 手作りの decode で本文を全部壊した
- 何: JSON エスケープの decode を自前の正規表現でやって取りこぼし、7 件の本文を文字化けさせて書き戻した
- 教訓: JSON / HTML の decode は `JSON.parse` / `CGI.unescapeHTML` など標準ライブラリに任せる。mass-update は最初の 1 件で「fetch → write → re-fetch → diff」を確認してから残りに流す

### 5. HTTP 200 を「公開成功」と判定した
- 何: 投稿 API が 200 を返したが実体は下書き保存のまま。「テストしました」が半分しか見ていなかった
- 教訓: 保存系・公開系は **再取得して実値を見る** まで完了と言わない。「テストしました」は「画面で / 匿名で / 別セッションで見える」まで

### 6. 意味を変えた API の呼び出し元と後続処理を見なかった
- 何: バックエンドの同期処理を「リセット」に変えたが、フロントのボタンが直後に別の取込を自動実行していて、修正後の値が全部戻った。検証のために本番で勝手に同期を回し、ユーザーの直前の編集も消した
- 教訓: 意味を変えた API は **フロントの呼び出し元と、その前後にチェーンしている処理を全部読む**（grep `'/api/path'` → 関数 → 続けて呼んでいる POST）。本番データを書き換える検証（同期・取込・リセット）は実行前に一言断る

### 7. 出力物の一部だけ見て「確認した」と報告した
- 何: フィルタ機能を足して「本番で確認した」と報告したが、既存 25 行の値が画面と違ったまま
- 教訓: 出力物の確認は **全行・全列を DB の実効値と機械的に突き合わせる**。「一部の見た目」だけ確認して完了と言わない。ある項目の意味を変えたら、その項目を読む全経路（画面・CSV・API・通知）を grep して影響を列挙する

### 8. 新しい経路を足したとき、既存経路の後処理を引き継がなかった
- 何: 挿入行の書き込みに既存行が持つ色付け判定を付け忘れ、逆に自分の判断で別の列を色付けした
- 教訓: 新経路を足したら既存経路と同じ後処理（整形・カウント・権限）が通るかをテストで固定する。色・順序・件数の意味は画面側の定義を正本にして勝手に拡張しない

## 着手前チェックリスト

### 破壊的操作なら
- [ ] 影響範囲（消えるもの / 戻せないもの）をユーザーに文章で見せた
- [ ] 非破壊的代替を 1 つ以上挙げた
- [ ] 「OK」「実行して」を貰った

### デプロイ・本番検証なら
- [ ] 向き先（URL・アプリ名・ポート）を設定ファイルの現物で確認した
- [ ] ENV 投入は正しい環境にやった
- [ ] 本番データを書き換える検証は実行前に断った
- [ ] `git remote -v` を関連する全リポジトリで確認した（兄弟ディレクトリ・入れ子に注意）

### 報告するなら
- [ ] 「テスト済み」= 実機で叩いた / 「未テスト」= 構文のみ を分けた
- [ ] 何が完了で何が残っているか箇条書きで明示した
- [ ] HTTP 200 / exit 0 だけで OK 判定していない（保存後の実値を最低 1 件は見た）

### mass-update / バックフィルを書いたら
- [ ] 最初の 1 件だけ流して fetch → write → re-fetch → diff で確認した
- [ ] decode は標準ライブラリに任せ、自前 regex で unescape していない
- [ ] テナントを明示して回した（`Current.tenant` が nil だと全テナントに書く）

## 自己更新ルール

新しいミスをやったら、`tasks/lessons.md` に「事象・原因・教訓」の 3 行で追記する。同じ型が 2 回出たらこのファイルの「型」に昇格させ、仕組み（ルール・フック・テスト）で防ぐ。
