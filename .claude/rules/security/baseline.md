# セキュリティ基盤（最低線）

> 「注意しましょう」を書かない。空いている穴を file:line 単位で塞ぐ。手順と実例は `/security-baseline`。

## 報告の規律

- 秘密の **値** を出力しない。出してよいのはパス・行番号・種別・有無。`cat .env` のように値ごと表示するコマンドを叩かない
- brakeman / npm audit が緑でも「安全の証明」にしない。秘密の混入・認可の欠落・Webhook の署名検証・平文保存は検出しない

## 実装前の確認

1. **秘密をリポジトリに入れない。** `git ls-files | grep -E 'master\.key$|credentials/.*\.key$|secrets\.yml$|\.pem$|client_secret_.*\.json$'` が 0 件。秘密は ENV か credentials。履歴に入った鍵は失効・再発行が本体で、履歴の書き換えは後
2. **`find(params[:id])` の直後に所有者スコープがあるか。** 認証主体の relation 起点（`current_user.articles.find`）か、直後の明示チェックか。無いなら「なぜ無くてよいか」をコメントで残す
3. **認証は既定で全部にかけ、外すものだけ `skip_before_action` で明示する。** パス前方一致の条件付き `before_action` を書かない
4. **CORS は完全一致の許可リストだけ。** `*` と部分一致正規表現を使わない
5. **トークンを URL クエリに置かない。** localStorage 保持は XSS 1 件で抜ける。新規に増やさず、既存分は httpOnly Cookie 移行の TODO として扱う
6. **外から来る値のシンクを追う。** params・ファイル名・外部 API 応答・DB に保存済みの入力が、シェル・ファイルパス・公開ディレクトリ・外部 HTTP・管理 UI・ログのどこに届くか。シェル実行の文字列連結、`public/` へのユーザーファイル保存、認証なしの管理 UI は差分に入った時点で P1

## 兄弟アクションの同値性

同じリソースを触るアクション（index / show / update / destroy、紐付け / 解除）を列挙し、防御レベルが揃っているかを見る。穴は「知らないから」ではなく「片方だけ書き忘れたから」空く。片方を直したら残りの欠落も件数とパスで報告する。

## 完了の定義（DoD）に足す行

- [ ] `gitleaks git --staged --no-banner --redact --exit-code 1` が 0 件
- [ ] Rails: `brakeman` / `bundler-audit` が緑。JS: `npm audit --omit=dev` の high が増えていない
- [ ] `find` を追加したら、所有者違い・他テナントで 403/404 かつ DB 不変のテストがある
- [ ] 管理画面・多テナント: 到達可能性表（アクション × 認証 × ロール × 所有スコープ × 副作用）を書いた
