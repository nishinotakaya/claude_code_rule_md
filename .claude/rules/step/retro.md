# STEP 10: 振り返り（PDCA）

デプロイ完了後、必ず実施する。

## 10.1 プロセスの振り返り

1. **ミスの有無**: 開発フロー・規約への違反、手戻り、無駄な作業はなかったか
2. **レビュー指摘の分析**: レビューで検出された違反は、実装指示の段階で防げたか
3. **サブエージェントの動作**: worktree 隔離は機能したか、委任状に足りない情報は無かったか
4. **品質**: 動作確認で想定外の挙動は無かったか。受け入れ基準は十分だったか
5. **証跡**: スクショ・レポートは揃ったか

## 10.2 教訓の記録

`tasks/lessons.md` に 1〜3 行で追記する:

```markdown
## カテゴリ名（日付）
- 事象 → 原因 → 次からどうするか
```

## 10.3 規約・フローの改善

仕組みで防げるものがあれば更新する。**同じミスは 2 度起こさない。人の注意力に頼らず、ルール・フック・テストで防ぐ。**

| 問題の種類 | 更新対象 |
|---|---|
| コーディングミスのパターン | `.claude/rules/coding/` に禁止パターン追加 |
| 破壊的操作・git のミス | `.claude/rules/git/` と `.claude/hooks/guard-bash.sh` |
| 開発フローの非効率 | `/develop` のステップ改善 |
| 認可・テナント境界の見落とし | `.claude/rules/security/` と `/security-baseline` |
| 環境・ポート・アカウントの陳腐化 | `.claude/rules/project/` |
| 受け入れ基準の不足 | `/auto-test` のシナリオ |

同じ指摘が 3 回出たら、レビュー観点ではなくルールかフックに昇格させる。
